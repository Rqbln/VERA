# ICSE 2027 SEIP paper — how to build and write it

`main.tex` is the ICSE 2027 Software Engineering in Practice paper. It is a
different paper from `apsec/main_apsec.tex`: no number, table or sentence of the APSEC
paper may reappear here, and the APSEC paper is cited, not recopied.

## Build

From `manuscript/`:

| Command | What it does |
|---|---|
| `make draft` | Draft PDF (`main.pdf`): drafting cockpit first, then the paper; prints the page report |
| `make paper` | The paper alone, without cockpit or plan markers (`main-clean.pdf`) |
| `make submit` | Submission build; fails on any placeholder, smoke table, APSEC number, page, spacing or font breach |
| `make check` | Full report on the last build: per-section budget, TBD list, decisions, guards |
| `make draft ARM=reduced` | Another ML-arm scenario (`full`, `reduced`, `withdrawn`); `make arms` builds all three |
| `make draft TITLE=B` | Another title option (`A`, `B`, `C`); `make titles` builds all three |
| `make section S=06b-fairness ARM=reduced` | One section file with the full preamble (`build/section-<S>-<ARM>.pdf`) |
| `make watch` | Rebuild on every save |
| `make tables BUNDLE=…zip` | Regenerate `tables/` and `figures/` from a vera-foundry replication bundle |
| `make tables-smoke` | Wire-test with vera-foundry's smoke results (stamped SMOKE DATA) |
| `make overleaf` | `build/overleaf.zip` for an Overleaf project |
| `make apsec` | Rebuild the submitted APSEC paper in `apsec/` |
| `make clean` | Remove every build product |

Variants never share an `.aux`: each gets its own job name under `build/`.
Overleaf has no Makefile and builds with the defaults at the top of
`support/preamble.tex` (full arm, draft mode, title A, `tables/`).

The author block lives in `authors.tex`, which is not version-controlled. The writing brief
(section plans, decision ids D1–D38, work ids E0–E8 and N1–N12) is
`private/VERA_ICSE2027_writing_brief.md` at the repository root, also not version-controlled.

## Layout

```
main.tex                 title options, author block, section order, bibliography
references.bib           bibliography of this paper (apsec/ keeps its own)
sections/*.tex           one file per section, 00-abstract to 11-availability
floats/*.tex             hand-built tables, and skeletons of the tables vera-foundry generates
support/preamble.tex     every package and macro (sections never define their own)
support/cockpit.tex      draft-only planning pages: page budget, contributions, scenarios,
                         evidence pipeline, floats, TBD list, decisions, detailed outline
support/pipeline.tex     experiments and new work -> sections -> artefacts, with live status
support/venue.tex        CFP constraints shown in the cockpit
support/decisions.tex    decisions with no single place in the text (\registerdecision)
support/apsec_guard.txt  APSEC numbers and phrases the checker refuses
scripts/check.py         the checker behind the page report
tables/, figures/        generated by `make tables` (never edited by hand; created on demand)
apsec/                   the submitted APSEC paper, frozen (see apsec/README.md)
```

## Writing conventions

Sections use planned units instead of `\section`, so that the cockpit can compare
each unit's roadmap budget with the pages it occupies:

```latex
\psection[roadmap]{key}{budget}{contributions}{owners}{Title}      % labels sec:key
\psubsection[roadmap]{key}{budget}{contributions}{owners}{Title}
\punsection[roadmap]{key}{budget}{contributions}{owners}{Title}     % unnumbered, e.g. Data Availability
```

The optional first argument is the roadmap's budget when the working budget differs; a budget
may depend on the scenario, e.g. `\armswitch{0.6}{0.6}{0.8}`.

Owners are `core`, `foundry`, `aicc`, `legal`, `dal`, `all`, comma-separated.

Until a paragraph is written, a plan stands in for it at its expected length:

```latex
\parplan[120]{Topic sentence of the paragraph.}{Evidence, sources, notes for the writer.}
```

The topic sentence is typeset in grey, followed by 120 grey filler words, so the page
count stays honest; the notes never reach the page and are listed in the cockpit's
detailed outline. Replace the whole `\parplan` with prose when writing the paragraph.

A number or fact that does not exist yet:

```latex
\tbd{E4}{foundry}{04 Oct}{share of requirements measured natively on API-served models}
```

typesets `[E4]` and joins the cockpit's TBD list with its owner and due date. Never
type a plausible number in its place. An open decision, with its id from the writing brief (`private/VERA_ICSE2027_writing_brief.md (not versioned)`, part c):

```latex
\decision{D5}{legal}{30 Sep}{Which group-fairness criterion is the institution's default?}
```

typesets `[D5]` and joins the cockpit's decision list, where each id appears once with every
section that raises it. `\registerdecision{id}{owner}{due}{question}` lists a decision without
typesetting anything (title, authors, venue: see `support/decisions.tex`).

Scenario-dependent text for the ML-arm decision of 30 September:

```latex
\armswitch{text if full}{text if reduced}{text if withdrawn}
\armnotwithdrawn{text present whenever the ML arm reports results}
```

Floats:

```latex
\plannedfloat{table}{tab:specs}{\columnwidth}{3.5cm}{Caption.}{What the table will show}
\generatedtable{table}{E4_measurability}{tab:e4_measurability}{\columnwidth}{4cm}{Caption.}{What it shows}
```

`\generatedtable` inputs `tables/E4_measurability.tex` once vera-foundry has produced it and
keeps the placeholder, under the same label, until then. The placeholder box has the
budgeted size: set the height to what the real float will take.

A value inside a table whose source a caption or paragraph already names: `\tbdcell` (a red
question mark, not listed). A hand-built float file in `floats/` starts with
`\registerfloat{label}{env}` so the cockpit lists it; skeleton files
(`floats/<file>-skeleton.tex`, a complete float with the generated table's label) stand in
for `tables/<file>.tex` until vera-foundry writes it.

Names that depend on decision D27 are macros: `\bankname{}`, `\aicc{}`, `\legalrisk{}`. Never
write a person's name in a `.tex` file.

Fixed terminology (settled 17 Sep): requirement names as the engine names them (Robustness, Cyber
resilience, Data adequacy, Copyright, Privacy, Capabilities, Calibration, AI disclosure, Watermark,
Representation bias, Fairness, Toxicity); *LLM arm* and *tabular arm*, *LLM specification* and
*tabular specification*; measurability states *native*, *fallback*, *not measurable*, *not
applicable*; cause classes *serving*, *set-up*, *by design*, *unknown*; *serving route* for the way
a deployment is served (the contributions say *serving mode*).

Other helpers: `\apsec` cites the APSEC paper; `\req{11}` prints R11; `\stnat`, `\stfb`,
`\stnm`, `\stna` are the native, fallback, not-measurable and not-applicable glyphs of
the measurability matrix; `\best{}` bolds a best cell as the generated tables do.

## Checks

`make draft` prints a brief report; `make check` the full one. In draft and clean
mode findings are warnings; `make submit` fails on any of them:

- body beyond 10 pages, or beyond 12 with references;
- any `\tbd`, `\parplan`, `\decision`, `\todo` or placeholder float left;
- a table generated from `results-smoke`;
- an APSEC-protected number or phrase (`support/apsec_guard.txt`) in the sources;
- LaTeX errors, undefined references or citations, overfull boxes wider than 2pt;
- a page size other than US letter, or a font not embedded;
- a document class other than `[10pt,conference]{IEEEtran}`, or any spacing change (`\vspace`,
  float or caption skips), which the call warns may lead to desk rejection;
- a missing or still provisional `authors.tex`.
